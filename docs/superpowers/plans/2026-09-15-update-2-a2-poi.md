# 主世界更新 2-A2 POI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保持无限 Chunk、地形、水体和道路核心稳定的前提下，加入确定性人工场景、环境装饰和可供未来采集系统使用的矿物节点接口。

**Architecture:** 新增独立 `PoiLayer`，以 256m cell 计算 `PoiPlacement`，从 `TerrainSampler` 读取道路、湖泊、Biome、Zone 和局部高度后选择 POI；WorldManager 只负责 owner chunk 的构建/销毁。主体网格使用低模组合，重复装饰使用共享 master + `createInstance`，矿物节点以稳定 metadata 保存。

**Tech Stack:** TypeScript 7, Babylon.js Core 9.26, Vite 8, Node `node:test` via `tsx`, Playwright。

## Global Constraints

- POI cell spacing 固定为 256m，每个 cell 最多一个主体 POI。
- 所有候选由 world seed + cell 坐标确定，不使用 `Math.random`。
- 不修改 TerrainSampler 高度/湖泊、水面几何、RoadLayer ribbon 或 chunk 半开范围。
- 建筑 footprint 坡度阈值为 0.32，footprint 高差阈值为 2.4m；桥端高度差阈值为 2.4m；失败时拒绝候选。
- 水边 POI 只使用合法湖泊 candidate；矿区只在 gravel + rocky/mountain 或高 rockiness 区域。
- 本阶段不做 NPC、任务、交互、经济结算和资源采集逻辑。

```ts
test("POI cell placement is deterministic and uses 256m ownership cells", () => {
  const sampler = new TerrainSampler(18421);
  const a = poiPlacementAt(-2, -3, sampler, 18421);
  const b = poiPlacementAt(-2, -3, sampler, 18421);
  assert.deepEqual(a, b);
  assert.equal(Math.floor((a?.x ?? 0) / 256), a?.ownerCellX);
  assert.equal(Math.floor((a?.z ?? 0) / 256), a?.ownerCellZ);

  assert.ok(metrics.maxSlope >= 0);
  assert.ok(metrics.heightRange >= 0);
});

test("mineral interface includes all four stable future resource types", () => {
  const kinds = new Set<MineralType>();
  for (let z = -2048; z <= 2048; z += 256) {
    for (let x = -2048; x <= 2048; x += 256) {
      const placement = poiPlacementAt(x / 256, z / 256, new TerrainSampler(18421), 18421);
      for (const node of placement?.minerals ?? []) kinds.add(node.type);
    }
  }
  assert.deepEqual([...kinds].sort(), ["copper", "iron", "rare", "stone"]);
});
```

- [ ] **Step 3: 实现最小规则层**

实现 `PoiRules.ts`：

```ts
export type PoiKind = "cabin" | "gasStation" | "warehouse" | "abandonedCamp" | "dock" | "woodBridge" | "roadBridge" | "mineShed" | "wreck" | "mineralOutcrop";
export type MineralType = "stone" | "iron" | "copper" | "rare";
export interface MineralNode { id: string; type: MineralType; amount: number; position: { x: number; y: number; z: number }; }
export interface PoiPlacement { id: string; kind: PoiKind; ownerCellX: number; ownerCellZ: number; x: number; z: number; groundY: number; rotation: number; roadDistance: number; minerals: MineralNode[]; }
```

`poiPlacementAt` 使用 `hashInts(cellX, cellZ, seed + 82_411)`，每格最多生成一个类型；道路型候选通过 `nearestRoadSpine` + 法线偏移，dock 使用 `nearestLakeCandidate` 的岸侧点，bridge 检查道路轴向两端，mine/mineral 仅接受 `sample.zone === "gravel"` 且 `sample.biome` 为 rocky/mountain 或 `rockiness > 0.62`。四类矿物按 hash 位段分配，位置 Y 使用 `sampler.height`。

`footprintMetrics` 在 footprint 四角、边中点和中心采样，使用相邻采样的有限差分计算最大坡度和高度范围；所有采样坐标保持稳定，不改变地形。

- [ ] **Step 2: 创建 PoiLayer 生命周期和材质缓存**

`buildForCell` 先调用 `placementFor`，创建 disabled master 后的 root `Mesh`，把主体和装饰 parent 到 root，保存 `builds` Map；`disposeCell` 对 root 递归 dispose，`disposeAll` 清空所有 active builds。共享装饰 master 使用 `createInstance(`${key}-poi-${id}`)`，实例设置 `isPickable = false` 且 `checkCollisions = false`。

- [ ] **Step 3: 实现十种主体组合**

使用箱体、圆柱、平面屋顶和低模多面体：小木屋为墙体+屋顶+烟囱，加油站为顶棚+两台油泵，小仓库为墙体+卷帘门，废弃营地为帐篷+篝火圈，码头为水平木板，桥为水平桥面+支柱，矿区工棚为棚屋+矿堆，废车点为车身+轮胎，矿物点为不同颜色矿石簇。所有主体位置来自 `PoiPlacement`，桥和建筑不沿地形强行旋转。

- [ ] **Step 4: 添加装饰和矿物 metadata**

在主体周边按 hash 生成围栏、路牌、电线杆、路灯、木箱、油桶、托盘、垃圾桶和长椅。矿物节点 mesh 写入：

```ts
mesh.metadata = { mineralNode: { id, type, amount, position: { x, y, z } } };
```

每种装饰使用共享 master + instance；装饰位置基于道路方向或 POI rotation，禁止 `Math.random`。
