# 可调节区块加载与性能审计设计

## 目标

为无限 Chunk 主世界增加类似 Minecraft 的可调节加载距离，并在不破坏当前地形、水体、道路和 POI 生成规则的前提下，降低运行时生成、渲染和卸载压力。

## 设计

### 加载距离语义

`chunkLoadRadius` 表示玩家所在 Chunk 周围的方形半径：半径 `r` 对应 `(2r + 1) × (2r + 1)` 个 Chunk。提供 2、3、4、5、6 五档，默认 3，保存到现有 `ai-world-pause-settings-v1` 设置中。这样玩家可以明确理解“加载距离”，并且不会把圆形距离与实际 Chunk 生命周期混在一起。

### 生命周期

WorldManager 使用当前设置值而不是编译期固定常量计算 wanted window。设置改变时：

1. 立刻移除窗口外的已加载 Chunk 与排队 Chunk。
2. 中心 3×3 立即构建，保证玩家脚下稳定。
3. 其余 Chunk 按距离优先进入唯一队列，每帧只处理固定预算。
4. 队列使用 key 集合去重，避免半径切换或快速移动造成线性 `some()` 扫描和重复候选。

Chunk 生成继续消费单份 TerrainGrid；不改动现有 Ground/Water/Road 的几何算法。

### UI 与持久化

ESC 设置新增“区块加载距离”下拉框，显示当前半径和预计区块数量。选择后立即调用 Game → WorldManager 的设置入口，保存设置并刷新窗口。窗口重建不改变世界 seed、已收集资源 ID 或玩家位置。

### 性能观测

WorldManager 发布只读性能快照：当前/目标/排队 Chunk、实例数、地标/POI、生成/卸载次数、最近一次窗口刷新耗时和每帧生成预算。浏览器验收在默认和低视距下检查：窗口数量正确、设置切换后超界 Chunk 被释放、队列不重复、主线程没有 page error，并记录连续帧的 FPS 与 `scene.getActiveMeshes()` 数量。

## 非目标

- 不重构地形、水体、道路和 POI 核心算法。
- 不引入 Web Worker、服务端联机或新的玩法系统。
- 不把远景地标的独立规则强行改成普通 Chunk 细节；只观察其随着 owner Chunk 正确卸载。

## 验收

- ESC 可切换 2/3/4/5/6 半径并持久化。
- 半径 `r` 始终最多保留 `(2r+1)^2` 个 Chunk，实际 Chunk 坐标不越界。
- 设置切换后旧窗口外对象、细节实例、交互和阴影 caster 均被释放。
- 快速跨 Chunk 时没有重复 Chunk、重复 POI 或不断增长的 pending 队列。
- `npm test`、`npm run build` 与浏览器性能验收通过。
