# 主页面设计规格

## 目标

为当前 Babylon.js 低模无限世界加入一个启动主页面，提供单人游戏、多​​人游戏入口、设置和操作说明，同时保持地形、水体、道路、POI 与游戏内 HUD 的现有边界不变。

## 视觉方向

主页面使用“航海日志 / 湖岸观测站”主题：蓝灰天空作为背景，深青黑半透明面板承载菜单，湖水青色作为交互高光。菜单展示实时暂停的主世界作为背景，使玩家进入游戏前能看到当前世界的低模环境。

主标题使用 `AI WORLD`，副标题使用“沿着道路，寻找下一片湖。”。信息分为三层：主操作、世界摘要、版本与操作提示。按钮文字使用用户能直接理解的动作词，不使用技术实现名称。

## 页面与状态

### 启动页

- `继续单人游戏`：使用当前本地存档进入主世界；没有存档时显示为 `开始单人游戏`。
- `新建单人存档`：清除当前 `economy-world-save-v1` 存档并重新载入默认出生点。
- `多人游戏`：进入多人说明页，明确标注“即将推出”。
- `设置`：进入设置页。
- `操作说明`：进入键位说明页。

### 多人说明页

说明联机功能尚未接入，列出未来目标“共享世界、协作探索、房间邀请”，所有尚未实现的动作按钮保持禁用；提供返回主页面。

### 设置页

- `减少动态效果`：保存在 `ai-world-settings-v1`，同步到 `document.documentElement.dataset.reducedMotion`，影响主菜单过渡和动画。
- `显示操作提示`：保存在同一个设置对象，控制 HUD 底部帮助条的初始显示。
- 提供返回主页面，不修改世界生成参数。

### 游戏中

启动页退出后继续使用现有 HUD 与 Esc 暂停菜单。主页面不会替换或重构现有暂停菜单，避免影响稳定的世界更新、存档和导航行为。

## 组件边界

- `MainMenu`：只负责主页面 DOM、页面内导航、设置持久化和按钮回调；不直接访问 Babylon 场景或 WorldManager。
- `Game`：负责创建 MainMenu、控制初始暂停状态、开始/新建单人游戏，并把设置动作映射到现有 HUD/存档流程。
- `Hud`：仅新增一个“显示操作提示”的受控方法；现有背包、湖泊导航和暂停菜单逻辑保持不变。
- `main.ts` / `index.html`：提供独立的 `main-menu-root` 容器。
- `styles.css`：新增主菜单样式，复用现有颜色语义，不改变世界渲染。

## 可访问性与响应式

按钮必须可用键盘焦点操作，禁用状态要有清晰视觉反馈；窄屏下主菜单改为单列，内容可滚动；尊重系统 `prefers-reduced-motion` 以及应用内“减少动态效果”设置。

## 测试验收

- 浏览器测试必须确认启动页存在、主菜单默认可见、单人按钮可以关闭菜单并解除暂停。
- 多人入口必须打开“即将推出”页并能返回。
- 设置开关必须写入并在刷新后恢复。
- 新建存档动作必须删除本地存档并触发默认世界重新初始化。
- `npm test` 与 `npm run build` 必须通过。
